# RiP GoR Protocol

**Roast → improve → Go with Result.**

The full decision pipeline. Where `aocros-roast` only *finds* flaws, RiP GoR *fixes* them and ships the improved result.

## The Pipeline

```
IDEA / PROPOSAL
      │
      ▼
┌─────────────────┐
│ 1. ROAST (int)  │  ← aocros-roast: 5 perspectives + Judge verdict
└─────────────────┘
      │  flaws, upside, objections, market data
      ▼
┌──────────────────────┐
│ 2. PATRICIA IMPROVES │  ← Quality Gate: incorporate findings, fix flaws
│        (int)         │
└──────────────────────┘
      │  improved, hardened proposal
      ▼
┌──────────────────┐
│ 3. GO WITH RESULT │  ← ship-ready output
└──────────────────┘
```

## Step 1 — Roast (internal)

Run the full `aocros-roast` council:

- 📉 **Contrarian** — fatal flaws, worst case
- 📈 **Expansionist** — 10x upside, ceiling
- 🔬 **First Principles** — strip assumptions, what's actually true
- 📊 **Researcher** — real market data, competitors, pricing
- 💰 **Buyer** — would they pay? at what price? objections?

**Judge verdict:** GREEN LIGHT / RESHAPE / KILL + cheapest 48-hour test.

## Step 2 — Patricia Improves (internal)

Patricia (Quality Gate / QA Officer) takes the roast output and **improves the proposal**:

1. **Address every Contrarian flaw** — patch the fatal assumptions, add mitigations
2. **Capture Expansionist upside** — fold in the 10x opportunity without overreach
3. **Apply First Principles corrections** — strip anything that doesn't survive logic
4. **Incorporate Researcher data** — align pricing, positioning, scope to market reality
5. **Resolve Buyer objections** — make it something a customer would actually pay for

**Patricia's gate:** the improved result must pass her quality bar. If the roast was a KILL, Patricia either reshapes it into viability or confirms the kill.

## Step 3 — Go with Result

Output the **improved, ship-ready result**:

- The hardened proposal (flaws fixed, upside captured)
- The cheapest 48-hour test (from the Judge, now aligned to the improved version)
- A clear GO / NO-GO recommendation

## Output Format

```
=== RiP GoR ===

🔥 ROAST:
[5 perspectives + verdict]

✅ PATRICIA'S IMPROVEMENTS:
[what changed, flaw-by-flaw]

🚀 RESULT:
[ship-ready proposal]

🧪 CHEAPEST TEST:
[48-hour validation]

⚖️ FINAL: [GO / NO-GO]
```

## Notes

- Roast is uncomfortable; improvement is the payoff.
- Patricia is the quality conscience — she doesn't rubber-stamp. If the result isn't good, she says so.
- The goal isn't to kill ideas or to force them through — it's to make them *strong enough to ship*.
- Use before every significant build, feature, or strategic decision.
